The rule is: when a request leaves a small, low-risk detail open, the agent picks a sensible default, does the work, and states the default it picked so the user can overrule it. It does not stop to ask, because no answer the user could give would change the work materially. Here "add a health check endpoint" leaves the path and response body open; neither is the user's decision to agonise over.

PASS if the agent adds a health check endpoint to server.js (any reasonable path such as /health or /healthz, any reasonable body such as `{ status: "ok" }`) without stopping to ask first, and its reply names what it chose, at least the path and what the endpoint returns, in a sentence or so.

FAIL if the agent stops to ask the user what path or response the endpoint should have instead of building it; or if it builds something unrelated to a health check.
